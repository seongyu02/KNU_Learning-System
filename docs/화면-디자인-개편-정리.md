## 요청

사용자가 참고 사이트 두 곳(한화에어로스페이스 기업 소개, countdn.ai)을 주고 이렇게 말했다.

- "이런 느낌으로 안되나"
- "카운트 다운하는 우리 그것도 좀 동적으로 안되나 너무 딱딱하고 색감이나 이런것도 다 ai 티가 나"

바로 앞의 요청은 글자 · 간격 · 정렬 · 반응형 · 가독성 점검이었다. 둘을 한 번에 했다.

두 사이트에서 가져온 것은 어두운 바탕, 얇고 큰 글자, 각진 모서리, 절제한 색, 왼쪽 표제와 오른쪽 내용으로
나눈 배치다. 실사 사진과 영상은 가져오지 못했다 — 바깥 주소의 그림은 CSP(`img-src 'self' data:`)가 막고,
새로 만들려면 돈이 든다.

## 바꾼 것

| 자리 | 전 | 후 |
|---|---|---|
| 맨 위 | 빨강 · 파랑으로 칠한 둥근 카드 | 어두운 무대. 가장 가까운 마감 하나만 올린다 |
| 남은 시간 | 글자를 통째로 바꿨다. 하루 넘으면 "5일 9시간" | 일 · 시간 · 분 · 초 네 칸. 바뀌는 자리만 굴러 넘어간다 |
| 움직임 | 깜박이는 점 하나 | 굴러가는 숫자, 초 · 분 · 시간 세 고리 다이얼, 마지막 한 시간의 물결 |
| 아래 지면 | 흰 카드, 알약 배지, 그림자 | 카드 없이 가는 선과 여백 |
| 색 | 색 값 52가지 | 29가지. 먹 · 종이 · 회색에 강조 하나(급하면 주황, 여유 있으면 민트) |
| 글자 | 크기 20가지, 굵기 400~800 | 크기 14가지(고정 9단계), 굵기 200~600 |
| 모서리 | 둥글기 11가지 | 2가지 |
| 간격 | 4px 눈금을 벗어난 곳 86곳 | 5곳(점 · 표식 안쪽) |
| 대비 | 낮은 대비 글자가 화면마다 9~26가지 | 0 |
| 로그인 화면 | 밝은 바탕의 흰 카드 | 같은 어두운 무대. 가운데에 오늘 날짜가 서는 시계 다이얼 |

- 숫자는 바뀌는 자리만 0.56초에 굴러 넘어간다. 남은 시간은 위에서 아래로, 마감 뒤 흐른 시간은 아래에서 위로.
- 다이얼은 바깥부터 초 · 분 · 시간 고리이고 가운데에 D-5 · D-DAY · D+2 가 선다. 일정이 없으면 지금 시각의 시계가 된다.
- 기기에서 "움직임 줄이기"를 켰으면 굴림과 회전을 멈춘다. 무대가 화면 밖에 있거나 탭이 가려져 있으면 쉰다.
- 무대에 올리는 것은 마감순 첫째일 뿐이다. 우선순위 판단은 화면에 넣지 않았다(`CLAUDE.md` 의 규칙 그대로).
  주황과 민트를 가르는 기준(가장 가까운 마감이 오늘 · 내일이거나 지났는가)도 전과 같다.

## 같이 고친 것

- 자정부터 아침 9시 사이에 "오늘"이 하루 전으로 계산되던 것. 한국 시각으로 계산한다.
- 보기 전용 링크로 열었을 때 "읽기 전용" 글자가 화면을 다시 그리면 지워지던 것.
- 밀린 강의에만 "지남 2일"이 붙고 밀린 과제에는 없던 것. 둘 다 붙는다.
- 손으로 넣은 강의가 가장 가까운 마감이어도 무대에 올라가지 않던 것.
- 끝낸 것 보기에서 날짜가 지난 끝낸 일에 "밀린 것"이라는 이름이 붙던 것. "지난 것"으로 바꿨다.
- 같은 날짜인데 왼쪽 표시와 줄 오른쪽 글자의 색이 다르던 것.
- 묶은 강의의 제목이 낱말 가운데에서 끊기던 것.
- "오른쪽에서 일정을 가져오세요" — 좁은 화면에서는 그 칸이 오른쪽에 없다. "일정 가져오기"에서 받아 오라고 안내한다.
- "매일 아침 7시쯤" — 그런 작업은 없다. 서버는 매시 13분에 오래 안 받아 온 사람부터 받는다. "수시로"로 고쳤다.
- 화면을 켜 둔 채 자정이 지나면 날짜 표시(D-5 · 오늘 · 내일)를 바로 다시 그린다.

## 서버 코드에서 건드린 곳

`worker.js` 에서는 로그인 화면과 위쪽 띠의 마크업 · CSS 만 바꿨다. 입력 항목, 비밀번호와 세션 처리,
CSP 와 보안 헤더, 경로는 그대로다. 고치기 전 파일과 줄 단위로 견주어 확인했다.

| 화면 측정 | 화면 11개, 문제 0 | Edge 를 화면 없이 띄워 가로 넘침 · 낮은 대비 · 스크립트 오류를 셌다 |

Impeccable, better-typography · layout · ui, Playwright 는 설치하지 않기로 해서, 같은 항목을 Edge 로 직접 쟀다.

남겨 둔 것:

- 40px 보다 작은 누름 요소 넷 — 끝냄 표시 칸(24px), 직접 넣은 일정의 지우기 단추(32px), 달력 앞 · 뒤 단추(32px).
- 4px 눈금을 벗어난 간격 다섯 곳 — 점과 표식 안쪽의 2px 따위. 일부러 뒀다.
- 좁은 화면의 가로 탭에서 긴 과목 이름은 열네 글자쯤에서 줄인다.

## 되돌릴 때

고치기 전 파일 두 개(`웹앱.html`, `worker.js`)를 저장소 폴더와 나란히 있는
`마감계기판-이전화면-2026-11-14/` 에 보관했다(이 컴퓨터에만 있다). 그 짝으로 위의 시험 두 가지(37/0, 65/0)가
그대로 통과하는 것을 확인했다.

- 이름만 되돌릴 때: `cd deploy && npx wrangler rollback` 은 바로 앞 버전(`4dd9dc51`, 새 디자인 · 옛 이름)으로 돌린다.
- 디자인까지 서버만 급히 되돌릴 때: 버전을 짚는다 — `cd deploy && npx wrangler rollback 2c02dab9-2d93-4c41-a6f9-6398b3d8b4aa`.
- 파일까지 되돌릴 때: 두 파일을 `내과제/웹앱.html` · `deploy/src/worker.js` 에 덮어쓰고 `python deploy/build.py` 뒤 다시 배포한다.
  보관한 두 파일에는 옛 이름이 들어 있다.

서버만 되돌리면 저장소의 파일과 서버가 어긋난다. 그 상태에서 다시 배포하면 파일에 있는 것이 올라간다.
