## 무엇을 만들었나

```
이캠퍼스 일정(iCal)  →  과제 / 강의 / 비교과 로 분류  →  마감목록.md
                                                          ↓
                          /오늘  ─ 가용시간을 묻고 우선순위를 계산 ─→  실행기록/
                                                          ↓
                                              다음 실행이 이 기록을 읽는다
```

**이 시스템의 핵심은 화면이 아니라 `실행기록/` 입니다.**
어제 뭘 하기로 했고, **뭘 안 했고 왜 안 했는지**가 거기 적힙니다.
그게 없으면 새 대화는 아무것도 모르는 상태로 시작합니다.

## 구조

```
KNU_Learning-System/
├── 과제소개.md                     제출 문서
├── 사용과개선.md                   제출 문서
├── CLAUDE.md                       프로젝트 지침 — 두 시스템의 경계, 물어야 할 결정
├── .claude/skills/
│   ├── 오늘/SKILL.md               오늘 할 과제를 정한다 (판단은 여기에만 있다)
│   └── 동기화/SKILL.md             이캠퍼스에서 받아 반영한다 (사람이 넣은 값은 안 덮는다)
├── 내과제/
│   ├── 일정가져오기.py             iCal 수집 · 4갈래 분류 · 대시보드 생성
│   ├── 마감목록.md                 원본 데이터 — 무엇이 남았나
│   ├── 실행기록/YYYY-MM-DD.md      상태 기록 — 세션을 잇는 고리
│   ├── 과목.md                     제외할 과목, 자동수집 사각지대
│   └── 웹앱.html                   웹 계기판 (Claude 아티팩트 · Cloudflare 공용)
├── deploy/                         Cloudflare Workers 무인 배포
└── netsvc-학습시스템/               수업에서 배포받은 학습 시스템 — 손대지 않았다
```

배포본은 **고치지 않고 그 구조(지침 · 행동 매뉴얼 · 기록 폴더)를 본떠 옆에 지었습니다.**
공부는 여전히 배포본의 `/study` 가, 과제는 `/오늘` 이 맡습니다.

## 써 보기

```bash
# 1. 달력 URL 등록 (최초 1회)
#    이캠퍼스 → /calendar/export.php → "모든 이벤트" + "현재와 추후 2달"
#    → 일정 URL 불러오기 → 내과제/.env.local 의 ICS_URL 에 붙여넣기
cp 내과제/.env.local.example 내과제/.env.local

# 2. 수집해 보기
python 내과제/일정가져오기.py

# 3. Claude Code 에서
/오늘 3시간
```

`.env.local` 은 커밋되지 않습니다. **달력 URL은 그 사람 일정 전체를 읽는 열쇠**라
`.gitignore` 에 넣고 `.env.local.example` 만 저장소에 둡니다.

## 실행에서 발견해 고친 것

문서로만 설계하고 끝냈으면 넷 다 못 찾았을 것들입니다.

| | 무엇이 틀렸나 | 어떻게 드러났나 |
|---|---|---|
| 1 | 강의 차시를 "과제가 아니다"라며 버렸다 | 수업 전에 볼 동영상 9개가 화면에 없었다 |
| 2 | iCal 의 UTC 시각을 KST 로 안 바꿔 강의가 하루 당겨졌다 | 금요일 수업이 목요일로 찍혔다 |
| 3 | 실행기록과 마감목록이 어긋나도 아무도 몰랐다 | 2회차가 두 파일을 대조하다 잡았다 |
| 4 | 강의의 **열리는 날**을 마감으로 읽었다 | 10/06까지 볼 수 있는 강의가 "지남 2일"로 떴다 |

이캠퍼스가 제목 일부를 **NFD(분해형 한글)** 로 내보내는 것도 여기서 잡았습니다 —
눈에는 한글인데 프로그램에게는 자모 낱개라 식별자가 통째로 비었습니다.

자세한 경위와 전후 비교는 [사용과개선.md](사용과개선.md) 에 있습니다.

## 알고 쓰는 한계

- **디지털트윈프로그래밍 · 단기 K-프로젝트I 은 이캠퍼스에 일정이 안 올라옵니다.**
  자동화로 못 메우는 구멍이라 주 1회 직접 확인합니다. 이게 이 시스템의 천장입니다.
- **제출 여부·시청 진도는 알 수 없습니다.** 일정 피드에 그런 칸이 없습니다.
  Moodle API 로는 가능하지만 이캠퍼스가 SSO 라 토큰 발급이 막혀 있습니다
  (`login/token.php` → `redirecterrordetected`).
- **마감 시각은 23:59 로 가정합니다.** 일정에는 날짜만 옵니다.

## 만든 것 · 쓴 것

Claude Code · Python(표준 라이브러리만) · Cloudflare Workers + D1
외부 연동은 이캠퍼스가 공식 제공하는 **iCal 일정 내보내기** 하나뿐입니다.

> 핵심 기능은 **파일과 스킬만으로 완결**됩니다.
> 화면과 서버는 그 위에 얹은 편의 장치이고, 없어도 시스템은 돌아갑니다.
