# 오늘 할 과제를 정한다 — 근거 없이 제안하지 않는다

이 스킬은 **할 일 목록을 뿌리는 스킬이 아니다.** 마감·소요시간·어제 남긴 것을 읽고
**오늘 실제로 끝낼 수 있는 것만** 골라내고, 그 선택의 근거를 남긴다.

## 이 스킬의 존재 이유 — 반드시 먼저 읽는다

과제를 놓치는 이유는 목록이 없어서가 아니다. **목록이 너무 길어서**다.
9개짜리 목록은 0개짜리와 똑같이 쓸모없다. 어느 것도 시작하지 못하게 만들기 때문이다.

> **절대 금지선: 가용시간을 모르는 채로 할 일을 제안하지 않는다.**
> 시간을 모르면 제안이 아니라 나열이다.

그리고 두 번째 금지선.

> **모르는 것을 추정하지 않는다.**
> 마감일이 없으면 지어내지 말고 "확인 대기"에 넣는다. 틀린 마감일은 없는 것보다 나쁘다.

---

## 내가 판단하는 것 vs 사람이 판단하는 것

이 경계를 지키는 것이 이 스킬의 전부다.

| 내가(자비스가) 계산한다 | 사람에게 반드시 묻는다 |
|---|---|
| 마감까지 남은 일수 | 마감일을 모르는 항목의 마감일 |
| 남은 소요시간 대비 여유 | 예상 소요시간 (내가 추정하지 않는다) |
| 어제 미완료 항목 이어받기 | 같은 날 마감이 겹칠 때 무엇을 먼저 할지 |
| 가용시간 초과 여부 | 포기·연기 결정 |
| 과제 / 강의차시 / 비교과 분류 | 분류가 틀렸을 때의 정정 |

---

## 0. 입력을 먼저 확보한다

`$ARGUMENTS` 에 가용시간이 있으면 쓴다. 없으면 **이것부터 묻는다.**

> "오늘 과제에 쓸 수 있는 시간이 몇 시간입니까?"

답을 듣기 전에는 1절로 가지 않는다. 오늘 날짜는 시스템에서 가져온다.

---

## 1. 자동 수집 — 이캠퍼스 일정을 받는다

```bash
python 내과제/일정가져오기.py          # 텍스트
python 내과제/일정가져오기.py --html   # 대시보드 HTML 갱신
```

일정은 **네 갈래**로 나뉜다. 과제만 보고 나머지를 버리지 않는다.

| 갈래 | 무엇인가 | 어떻게 다루나 |
|---|---|---|
| **과제** | 날짜만 있는 이벤트. 제출물 | 우선순위 계산 대상 |
| **강의차시** | 시각이 붙은 이벤트. 동영상·열람기간 | **별도 트랙으로 보여준다.** 과제 목록에는 안 섞는다 |
| 비교과 | 과목 칸이 32자리 16진수 | 안 보여준다 |
| 제외과목 | `과목.md` 에서 `X` 인 과목 | 안 보여준다 |

**강의차시는 제출물이 아니지만 해야 할 일이다.** 수업 전에 봐야 하는 동영상이 여기 있다.
버리지 말고 "당장 봐야 할 강의"로 따로 내놓는다.

**강의차시의 날짜는 마감이 아니라 열리는 날이다.** 이캠퍼스 DTSTART 는 시청이 **열리는** 때,
DTEND 는 **닫히는** 때다. 스크립트 표의 첫 칸(`열림`)이 열리는 날, 다섯째 칸(`닫힘`)이 닫히는 날이다.
열린 지 며칠 된 강의를 "지남"이라고 말하지 않는다. 닫히는 날이 지나야 밀린 것이다.
**동영상 강의는 전부 반드시 봐야 한다**(사용자 확인, 2026-09-24). 닫히는 날이 곧 시청 마감이다.
(실제로 09-22 에 열린 게임프로그래밍 4주차가 "지남 2일"로 잘못 올라갔다. 10-06 까지 볼 수 있었다.)

- 성공하면 과제 후보 표가 나온다. `마감목록.md` 에 없는 항목을 **새로 발견한 것**으로 표시한다.
- `[중단]` 으로 시작하는 메시지가 나오면 **멈추지 말고 2절로 간다.**
  자동 수집은 편의 장치다. 토큰이 만료돼도 `마감목록.md` 만으로 일할 수 있어야 한다.
  사용자에게는 한 줄만 알린다 — "자동 수집 실패, 저장된 목록으로 진행합니다."

**새로 발견한 항목은 예상소요가 비어 있다.** 우선순위 계산에 넣지 말고 3절에서 묻는다.

## 2. 기록을 읽는다 — 이 스킬의 핵심

```
내과제/마감목록.md          → 무엇이 남아 있나
내과제/실행기록/ 최신 파일   → 어제 뭘 하기로 했고, 뭘 못 끝냈나
내과제/과목.md              → 제외할 과목, 자동 수집 사각지대
```

**실행기록의 미완료 항목은 오늘 목록의 맨 앞에서 검토한다.** 새 항목처럼 다시 제안하지 않고
`(이어받음, N일째)` 를 붙인다. 이틀 이상 밀린 것은 그 사실 자체를 사용자에게 말한다 —
계속 밀리는 항목은 소요시간을 잘못 잡았거나 시작을 못 하고 있다는 신호다.

### 두 파일이 어긋나면 먼저 멈춘다

`실행기록` 의 완료 표시와 `마감목록.md` 의 상태를 **대조한다.** 어긋나면 그냥 넘어가지 않는다.

> "1회차는 `{항목}` 을 완료로 찍었는데 마감목록은 `진행중` 입니다. 어느 쪽이 맞습니까?"

**어느 쪽이 맞는지 내가 정하지 않는다.** 확인받은 뒤 두 파일을 같이 고치고,
정정했다는 사실을 기록에 남긴다. 지우고 덮어쓰지 않는다.

실제로 이 일이 터졌다 — 1회차가 실행기록에만 `[x]` 를 쓰고 마감목록은 그대로 뒀다.
두 파일을 다 읽었기 때문에 잡혔지, 한쪽만 읽었으면 끝난 과제로 넘어갔을 것이다.
**기록이 두 벌이면 어긋난다. 어긋나는 건 막을 수 없으니 발견하는 절차를 둔다.**

## 3. 정보가 모자라면 여기서 멈추고 묻는다

다음에 해당하는 항목이 있으면 **제안을 만들기 전에** 묻는다.

| 상황 | 행동 |
|---|---|
| 예상소요가 비어 있다 | "새로 발견: N건. 각각 몇 시간쯤 걸릴까요?" — 추정하지 않는다 |
| 마감일이 없다 | `마감목록.md` 의 **확인 대기** 표로 보내고, 오늘 목록에는 안 올린다 |
| 같은 날 마감이 2건 이상 | 배점과 남은 분량을 묻고 **사람이 고르게 한다** |
| 자동 수집 분류가 의심스럽다 | "이건 과제가 맞습니까?" 한 번 확인한다 |

한꺼번에 다 묻지 않는다. **오늘 제안에 실제로 영향을 주는 것만** 묻는다.
D-13 짜리 과제의 소요시간은 오늘 안 물어도 된다.

## 4. 우선순위를 계산한다

> **이 절과 5절은 `내과제/웹앱.html` 의 `computePlan()` 에도 구현돼 있다.**
> 웹에는 Claude 가 없어 이 문서를 읽을 수 없기 때문이다. 여기가 원본이다.
> **고치면 두 곳을 같이 고친다.** 한쪽만 고치면 대화와 화면이 다른 답을 낸다.

```
① 마감이 오늘이거나 지났다        → 무조건 1순위. 가용시간을 넘겨도 올린다(경고를 붙여서)
② 남은일수 ÷ 남은소요시간 이 작은 순  → 여유가 없는 것부터
③ 같은 순위면 이미 착수한 것 먼저    → 다시 붙는 비용이 있다
```

계산에서 **제외**하는 것: 과목.md 에서 `X` 인 과목, 비교과, 강의차시,
예상소요를 모르는 항목, 마감일을 모르는 항목.

## 5. 제안한다 — 최대 3개, 가용시간 안에서

- **3개를 넘기지 않는다.** 시간이 남아도 넘기지 않는다.
- 합계 소요시간이 가용시간을 넘으면 넘는 항목을 뺀다. 뺀 것은 "오늘 안 함"으로 보여준다.
- **각 항목에 왜 이걸 골랐는지 한 줄을 붙인다.** 근거 없는 제안은 하지 않는다.
- 가용시간이 그 항목 최소 착수 단위보다 작으면 **"오늘은 착수만"** 을 제안하되,
  할지 말지는 사람이 정한다.

출력 형태:

```
오늘 (2026-09-24, 가용 3시간)

1. [D-0] 네트워크서비스 · 나만의 자비스 만들기 — 3h
   오늘 마감이다. 다른 걸 할 여유가 없다.

오늘 안 함
- 머신러닝 3주차 과제 (D-4) — 오늘 마감 건에 시간을 다 씀

당장 봐야 할 강의
- 네트워크서비스 4-1 ~ 4-9 (내일 09-25, 수업 전 시청)
- 게임프로그래밍 4주차 (09-22 열림, 10-06 닫힘)

확인 필요
- 10-07 네트워크서비스 과제 2건이 같은 날이다. 별개 과제인지 확인 필요
```

**강의 트랙은 3개 제한에 포함되지 않는다.** 제출물이 아니라 별도 트랙이기 때문이다.
다만 시청 시간이 가용시간을 잡아먹는다는 것은 알려준다.

## 6. 기록한다 — 안 하면 이 시스템은 없는 것과 같다

사용자가 제안을 확인하면 `내과제/실행기록/YYYY-MM-DD.md` 를 만든다.

```markdown
# 2026-09-24

가용시간: 3시간
자동수집: 성공 (18건 중 과제 4건)

| 항목 | 과목 | 마감 | 예상 | 완료 | 실제 | 메모 |
|---|---|---|---|---|---|---|
| 나만의 자비스 만들기 | 네트워크서비스 | 09-24 | 3h | [ ] | | |

## 오늘 안 한 것과 이유
- 머신러닝 3주차 (D-4) — 오늘 마감 건 우선

## 확인 대기
- 10-07 네트워크서비스 과제 2건 별개 여부
```

세션 중 "끝냈어" 를 들으면 **두 파일을 같이 고친다.**
실행기록의 `완료` 칸과 `마감목록.md` 의 상태를 함께 바꾼다. 한쪽만 고치면 다음 실행이 어긋난다.

## 7. 완료 기준

이 세 가지가 다 돼야 끝난 것이다.

1. `실행기록/오늘날짜.md` 가 존재한다
2. 각 항목에 완료 여부 칸이 있다
3. 제안하지 않은 항목은 **이유와 함께** 기록돼 있다 — 다음 실행이 이걸 읽는다

---

## 절대 하지 않는 것

- 가용시간을 모르는 채로 할 일을 제안하는 것
- 한 번에 4개 이상 제안하는 것
- 마감일이나 소요시간을 **추정해서** 채워 넣는 것
- 어제 미완료 항목을 새 항목처럼 다시 올리는 것
- 신입생세미나II 를 할 일로 올리는 것 (멘토라 과제가 없다)
- 강의 차시·비교과 특강을 **과제 목록에 섞는** 것
- 강의 차시를 "과제가 아니다"라며 **아예 안 보여주는** 것 — 수업 전에 봐야 할 동영상이다
- 자동 수집이 실패했다고 아무것도 못 한다고 말하는 것
