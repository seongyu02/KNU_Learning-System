# 이캠퍼스 일정을 받아 반영한다

마감이 **네 군데**에 있다. 이 스킬은 그것들을 한 방향으로 맞춘다.

```
이캠퍼스 (원천)
   └→ 마감목록.md      저장소의 원본 데이터. 사람이 읽고 고치는 곳
   └→ 대시보드.html    로컬 화면 (생성물)
   └→ 서버 D1          배포된 웹앱이 읽는 곳
```

## 웹앱의 "지금 동기화" 버튼과 다르다

버튼은 **이 스킬을 거치지 않는다.** 브라우저가 서버를 직접 부르고, 서버가 혼자 받아온다.

| | 버튼 | 이 스킬 |
|---|---|---|
| 서버 D1 | 갱신함 | 갱신함 |
| **`마감목록.md`** | **안 건드림** | 갱신함 |
| **새 과제 소요시간** | **안 물음** | 물음 |
| 로컬 대시보드 | 안 만듦 | 만듦 |

**`마감목록.md` 가 `/오늘` 이 읽는 판단의 원본이다.** 버튼만 계속 누르면 웹 화면에는
새 과제가 보이는데 `/오늘` 은 그것을 모른다.

사용자가 "웹에서는 보이는데 왜 오늘 목록엔 없냐"고 하면 이게 원인이다.
이 스킬을 한 번 돌려서 `마감목록.md` 에 넣으면 해결된다.

## 이 스킬의 존재 이유 — 반드시 먼저 읽는다

**기록이 여러 벌이면 반드시 어긋난다.** 실제로 어긋났다 — 실행기록에만 완료를 찍고
마감목록은 그대로 둔 적이 있다. 어긋나는 걸 막을 수는 없으니 **한 방향으로 흐르게** 만든다.

> **이캠퍼스가 원천이다. 사람이 넣은 값은 덮지 않는다.**
> 예상소요·완료표시·메모는 사람이 넣은 것이다. 동기화가 이것들을 지우면
> 매번 처음부터 다시 적어야 하고, 그러면 아무도 안 적는다.

두 번째 금지선.

> **새로 발견한 항목의 소요시간을 추정하지 않는다.**
> 모르면 비워두고 묻는다. 비어 있는 값은 우선순위 계산에서 빠진다.

## 0. 무엇을 할지 정한다

| `$ARGUMENTS` | 하는 일 |
|---|---|
| 비어 있음 | 수집 → 마감목록 갱신 → 대시보드 → 서버. 전부 |
| `확인만` | 수집해서 **새 항목만 보고**한다. 파일을 고치지 않는다 |

## 1. 수집한다

```bash
python 내과제/일정가져오기.py
```

출력은 **과제 / 강의차시 / 제외** 로 갈려 나온다. 분류 규칙은 스크립트 안에 있고,
바꾸려면 `classify()` 와 `deploy/src/worker.js` 를 **같이** 고쳐야 한다 (3절 참고).

`[중단]` 이 나오면 멈추고 사용자에게 알린다.

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `HTTP 403` / `404` | **달력 URL 만료** | 이캠퍼스에서 다시 받아 `.env.local` 교체 |
| `.env.local 이 없습니다` | 설정 안 됨 | `.env.local.example` 을 보고 안내 |
| 연결 실패 | 네트워크 | 잠시 뒤 다시 |

## 2. 새 항목을 가려낸다

`내과제/마감목록.md` 를 읽고 **거기 없는 것만** 새 항목이다.

- 이미 있는 항목은 **건드리지 않는다.** 예상소요·상태·메모가 사람의 값이다.
- 새 항목이 없으면 "새 마감 없음" 한 줄로 끝낸다. 파일을 괜히 고치지 않는다.
- 새 항목이 있으면 **먼저 보여주고** 마감목록에 넣을지 확인받는다.

## 3. 소요시간을 묻는다 — 추정하지 않는다

새로 들어온 과제는 예상소요가 비어 있다.

> "새 과제 N건입니다. 각각 몇 시간쯤 걸릴까요? 모르시면 '모름' 이라고 하세요."

- 답을 받으면 `마감목록.md` 에 적는다.
- `모름` 이면 **확인 대기** 표로 보낸다. 비워두는 것이 지어내는 것보다 낫다.
- 강의차시는 묻지 않는다. 시청은 소요시간으로 관리하지 않는다.

## 4. 반영한다

**마감목록.md** — 새 항목을 표에 추가한다. 기존 줄은 손대지 않는다.

**대시보드** (로컬 화면)

```bash
python 내과제/sync.py
```

**서버** (배포돼 있을 때만). 화면의 **지금 동기화** 버튼과 같은 일을 한다.

```bash
curl -s -X POST "https://deadline-dashboard.a92875664.workers.dev/api/sync?t=<APP_TOKEN>"
```

`APP_TOKEN` 은 `내과제/.env.local` 에 있다. **값을 화면에 출력하지 않는다.**
`{"ok":true,"found":N,"added":M}` 가 정상이다. `added` 는 서버에 새로 들어간 수다.

> 서버는 `INSERT OR IGNORE` 라 이미 있는 항목을 덮지 않는다.
> 저장소와 서버가 따로 놀 수 있다 — 완료 표시는 웹앱에서, 소요시간은 양쪽에 들어간다.
> **완전 일치를 보장하지 않는다.** 원천은 이캠퍼스이고, 판단의 원본은 `마감목록.md` 다.

## 5. 보고한다

한 화면에 들어가게 짧게.

```
수집 18건 → 과제 4 / 강의 11 / 제외 3
새 과제 없음
대시보드 갱신 · 서버 반영 (found=15, added=0)
```

새 항목이 있으면 제목·과목·마감을 표로 붙인다.

## 6. 완료 기준

1. 사용자가 **새 마감이 있는지 없는지** 알게 됐다
2. 새 항목이 있었다면 `마감목록.md` 에 들어갔고, 소요시간을 물었다
3. 실패했다면 **무엇이 실패했고 어떻게 고치는지** 말했다 — 조용히 넘어가지 않는다

## 자동 수집이 못 잡는 것

**디지털트윈프로그래밍 · 단기 K-프로젝트I 은 이캠퍼스에 일정이 안 올라온다.**
동기화를 아무리 돌려도 안 나온다. 주 1회 강의실을 직접 확인해 수동 등록해야 한다.
사용자가 "왜 이 과목이 없냐"고 물으면 이 사실을 말한다. 찾아보는 척하지 않는다.

`과목.md` 에 사각지대가 적혀 있다. 과목이 늘거나 줄면 거기를 먼저 고친다.

## 절대 하지 않는 것

- 이미 있는 항목의 예상소요·완료표시·메모를 덮어쓰는 것
- 새 항목의 소요시간을 추정해서 채우는 것
- `.env.local` 의 값(달력 URL, APP_TOKEN)을 대화에 출력하는 것
- 새 마감이 없는데 파일을 고쳐 커밋을 만드는 것
- 수집이 실패했는데 "반영했습니다" 라고 말하는 것
- 신입생세미나II 를 목록에 올리는 것 (멘토라 제출물이 없다)
